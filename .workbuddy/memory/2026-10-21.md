## 更正（同日，用户澄清口径）

**上一版把本地页做成"默认不常驻 UI"，方向错了。** 用户的验收口径是：「打开一个本地 HTML → 应有悬浮球」。
已提交 `be77f6f` 改回：去掉 `AUTO_MOUNT_UI` / `IS_LOCAL_PAGE` 门控，`initAssistant` 对所有页面无条件
`ensureHost()`，划词气泡同样恢复。

需求 2 因此改为由两件事承担（都已在测）：
1. `save-clean.js` 在 Ctrl+S / beforeprint 那一刻把宿主**摘出文档**，focus/交互后原位插回；
2. 图标只在 shadow root 内，页面自己 `outerHTML` 序列化取不到 —— 产物最多留一个空壳 `<div id="__kb-ai-host">`，没有图标。

**教训（写进本仓库的偏好）**：产品默认值的取舍不要用"减少入口"去换"技术上的干净"，
入口消失对用户就是"功能没做"；干净应当在导出路径与 DOM 结构上解决。

## 修复：保存出来的副本里仍有悬浮球（用户实测反馈）

**根因（真浏览器实测，不是推断）**：Edge/Chromium 的「另存为」用 PageSerializer，
会把 **open shadow root 一起序列化**成声明式 shadow DOM（`<template shadowrootmode="open">`），
存档里因此带着 `.fab`、`chrome-extension://…/recallflow-mark.svg` 和整份面板 CSS。
我之前"shadow 内容不会被序列化"的判断是错的 —— 这是本轮最重要的教训：
**涉及浏览器行为时，先 captureSnapshot 实测，再下结论。**

实测对照（chromium + `--load-extension` 真扩展，CDP `Page.captureSnapshot`）：
- 实时页：`#__kb-ai-host` 是 DIV，.fab 52×52；
- 存档副本（宿主 + 声明式 shadow）：球照旧 52×52（这就是用户看到的）。

**最终方案（不依赖"拦住保存动作"，因为菜单/右键另存为不发 keydown）**：
1. 宿主改自定义元素 `rf-ai-host`，由 **MAIN world** 的 `lib/page/debug-hook.js` 注册
   —— 实测隔离世界里 `customElements` 是 **null**（typeof 仍是 'object'），不能在这边 define；
2. `PANEL_CSS` 加 `:host(:not(:defined)) { display:none !important }`；
   存档无脚本 ⇒ 不升级 ⇒ 整个 UI 隐藏。`:defined` 是运行期状态，不进 HTML；
3. 自定义元素必须用 `class` 定义：ES5 `function + Reflect.construct` 在"先创建后升级"路径
   返回另一个实例，页面旧节点原型链坏掉（实测 `host.matches is not a function`）；
4. `ensureHost` 挂载前清掉页面里遗留的旧宿主（旧存档里写死的那个），避免"死图标 + 新球"两个；
5. `save-clean.js` 保留为第二层（Ctrl+S / beforeprint 摘除宿主）。

**门禁**：`tests/e2e/save-clean.spec.mjs`（3 条：实时可见 52×52 / 存档副本 display:none 0×0 /
残渣被清），已接入 `scripts/run-e2e.mjs`；`tests/page-debug-hook.test.mjs` 的 vm 沙箱补
customElements/HTMLElement 桩并断言注册（行为断言，避开"读源码"棘轮）。
全量 1842 项通过；提交 `cc0bd4d`。
