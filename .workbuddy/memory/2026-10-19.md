## 迭代分支 `opt/agent-and-test-iteration`（58 轮，1734 项 / 148 文件全绿）

台账见 `docs/optimization-iterations.md`。**期间修掉的 4 个真 bug 全是被"补断言"逼出来的，
不是读代码读出来的** —— 这条经验值得记住：

1. **并行工具调用从未执行**（两个叠加 bug）：`agent.js` runParallelBatch 的 `remaining` 恒 0；
   且 `TOOL_REGISTRY` + `getToolMetadata` 都漏掉 `parallelSafe`，14 个工具全被判不可并发。
   修完第一个后测试仍红，才发现第二个。**系统提示早已向模型承诺并发。**
2. **画像提升后完成校验永久失效**：`intent` 是运行期常量，`promoteToResearch` 不改它。
   修法是新增 `resolveVerifyIntent(intent, promoted)` 并让主循环用有效意图。
3. `describeToolFailure` 遇"无 message 的错误对象"产出 `[object Object]` 喂给模型。
4. **恒真断言**：`deepEqual(warnedAt, REPEAT_THRESHOLDS.slice())` 两边同源于一个常量，
   改常量两边一起变。期望值必须是字面量。

## ⚠ 覆盖率数字不可信（重要，别用它写"提升了多少"）

node `--test --experimental-test-coverage` 在"同一模块被多个测试文件加载"时跨进程合并不可靠：
两文件串行表现为 last-writer-wins（cdp：顺序决定 44.09% 或 58.41%）；全量并发两次两个结果；
但 agent.js 全量 41.76% vs 逐文件取最大 27.26%，又不符合 last-wins。三个数都不是真值。
**唯一可靠信号是"完全没被加载"** —— `page/chat.js`（4975 行）有 12 个测试文件提到它却零覆盖
（全是读源码做正则），这是真零，也是没啃下来的最大空洞（需要 DOM 桩）。
