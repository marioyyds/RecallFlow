Quick start

From download to running: just four steps.

  1. Load the unpacked extension

    Open edge://extensions/, enable “Developer mode”, choose “Load unpacked” and point it at the project directory.

  2. Configure your DeepSeek API Key

    Click the extension icon to open Settings and fill in your own DeepSeek API Key. Without it, the knowledge base still works.

  3. Use the bubble on the right of the page

    Open any web page, click the “RecallFlow” bubble on the right, type an instruction, or pick a quick phrase.

  4. Optional: allow access to file URLs

    To operate local HTML you opened by double-clicking, turn on “Allow access to file URLs” in the extension details; after that, local pages behave like any web page.

Core capabilities

The target is every element on a web page: cross-origin iframes, Shadow DOM, canvas, virtual lists, upload / drag-and-drop / cascading selects, pagination and infinite scroll.

  • Across iframes / Shadow DOM / canvas

    Locate and operate inside the real structure of the real page, without guessing at the DOM.

  • Upload, drag-and-drop and cascading selects

    Covers custom date pickers, file uploads, drag-to-sort and cascading selects; when synthesized events fall short, trusted events are dispatched over CDP.

  • Pagination and infinite scroll

    Keeps operating after paging or scroll-loading; targets inside virtual lists are hit too.

  • Carry data across pages

    Move information from one page to another — read, click, fill and drag can be chained into one flow.

  • Remembers and reuses

    Site memory, skills and macros make repeated flows reusable; all data is stored locally.

  • Failure soft landing and observability

    On repeated calls or consecutive failures it only injects reflection suggestions and does not remove tools; tools, timings and the run trace are recorded round by round.

For what guarantees each capability (fixture pages / scripts / E2E / skills / criteria), see Capability inventory.

Agent design

After receiving an instruction it assembles context; model output goes through the tool guard and graded approval; execution results flow back to the model; before the final answer there is one more completion check.

  1. Receive instruction

    Assemble context: intent routing, system prompt, history and budget.

  2. Model output

    Tool calls go to the tool guard; the final answer goes to the completion check.

  3. Graded approval

    Graded by risk and site trust; tools execute once approved.

  4. Execute and feed back

    Execution results go back to the model for the next round; when there is no progress, only reflection suggestions are injected.

  5. Completion check

    If it is not met, inject reflection and continue; once met, deliver the answer.

  • Failure soft landing: on repeated calls, consecutive failures or no progress, it only injects reflection suggestions and does not decide for the model; it wraps up only when there is sustained no-progress across tools or the budget is exhausted.
  • Unified registry: the model's tool list, permission policy and parameter validation share a single definition.
  • Reliability and observability: sessions shared across the browser, run lock, stall detection and before-and-after action snapshot verification, with per-round cache hit rate and latency breakdown.

For the full flowchart, see Page operations E2E flowchart.

Integrating with external AI (MCP)

SPAs, logged-in pages or intranet pages that webfetch cannot read are handed to RecallFlow, which reads them over a real browser session and returns evidence with timestamps and hashes; external agents can also touch the page through the single write channel page_action, forming a “read → change → verify” front-end debugging loop.

The single source of truth for the integration roadmap is docs/integration-status.md; installation and configuration are in recallflow-mcp/README.md.
