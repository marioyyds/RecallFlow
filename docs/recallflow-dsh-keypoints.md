## 一、现在要做的两件事（就这两件）

| 动作 | 影响哪一侧 | 解决什么 |
|---|---|---|
| **重启 DSH** | 插件（启动时载入）| `语义=[object Object]`（已确认解决）|
| **重载扩展 + 刷新页面** | 扩展（内容脚本，加载时读取）| 消息发两条 / chip 不消失 / 刷新后 markdown 变裸记号 |

**为什么必须分两侧**：插件代码在 DSH 启动时载入；扩展代码在浏览器加载扩展时读取。
**代码改完不重载 = 没改** —— 这一路有四次"修好了但没生效"，每次都要先确认**是哪一侧**。

**验完的标志**：刷新/重开面板 → markdown 正常（不再有裸 `**粗体**` / `###`）；拾取一个元素发送 →
只收到**一条**、摘要里没有 `[object Object]`、chip 随即消失，且**下一条消息不再带着那个元素**。

## 三、已确认的事实（别再重新猜一遍）

- **DSH 的 `agents.list()` 只给"活着的" agent**（类型原文 *"All **live** agents"*）；
  `SessionStore` 是"已载入会话"登记表，不是历史索引。
- **插件拿不到 `sessionController`**（实测 `available:false`；`ctx.remote` 是 `ClientRemote`，
  而 Cordis 连**读**它都要求先在 `inject` 里声明 → 报 `cannot get property "remote" without inject`）。
  → **结论：插件无法把一条没载入的会话载入**；想给它发消息，只能**先在 DSH 里打开它一次**。
- **会话清单能列全**：走 `sessionQuery.listSessions()`（实测 17 条）。
  **子会话用 `SessionHeader.parentSession` 判** —— 17 条里有 4 条是子会话，
  其中一条**带 `session-` 前缀**，所以**不能靠 id 形状猜**。
- **会话历史能读**：`readSession` 注释写明参数是 *"live or persisted session id to read"*。
- **面板 = 同一条 DSH 会话的另一个视图**。所以：**扩展不能删**（它是唯一能碰页面的那一端：
  内容脚本、MAIN-world 钩子、CDP）；但**气泡（面板）可以不要**，用 DSH GUI 替代 ——
  代价是划词气泡、页面内引用高亮、rpcId 回声对齐、以及"不切标签页就能问"这些要重做或放弃。

## 四、踩过的坑 → 下次直接用

1. **看不见的路径不算数**。面板在 shadow DOM 里，普通 DOM 快照看不到；
   所以关键状态一律写进 `/status`（`sessionStore` / `sessionController` 自检字段就是这么来的）。
2. **单测喂的形状必须和真机一致**。`elementsDigest` 的 `[object Object]` 就是因为单测喂**字符串**、
   真机给**对象**；同一个坑：`readSessionOk` 恒 false 是探针自己的**时序 bug**、
   后来还有一次**早退** bug（`if (!c) return;` 把整段后续跳过了）。两次都骗了我一整轮。
3. **顺序错了会静默重复**。`sendPanelTurn` 是异步的，而推送游标原来只在 `.then()` 里推进 ——
   回声走 WS、可能先到，于是那条用户消息被**再发一遍**。修法是"发起发送**之前**就推进游标"。
   **静态断言**（"A 必须在 B 之前"）是这类 bug 最便宜的闸。
4. **实时路径修了，恢复路径别忘**。markdown 那次：实时回声用 `renderAnswer`、
   恢复渲染器却用 `escHtml` → 刷新后满屏裸 `**粗体**`。
   见到"**刷新后才不对**"就按这条线查恢复路径。
5. **断言别写死形状或长度**。有一条断言靠"截取整段消息体"，窗口从 300 放宽到 900，
   **两次都是因为加注释/字段就红** —— 红的是测试不是代码。改成钉独立事实。
6. **加了会留在界面上的状态，就要在成功之后清掉**。chip 不消失就是这么来的：
   发送时带上了拾取的元素，却从没清空 → 之后**每条消息**都带着它。
7. **扩展侧改动要用户重载才生效** —— 所以我先把能测的测掉（桩测试、静态契约），
   再明确告诉用户"这一步是你要做的"。
